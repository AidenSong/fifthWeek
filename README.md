# 시나리오에러 발생할 수 있는 동시성 이슈
## 1.회원 금액 충전 / 사용
* 사용자가 동시에 포인트를 충전하거나 사용할 떄 발생
* 여러 페이지를 띄워놓고 한 페이지에서는 충전을 한 페이지에서는 사용할 경우.
### Pessimistic Locking (비관적 락)
* 구현 복잡도 ⬇
* 성능 ⬇
* 효율성 ?
* 이유
  * 개인만 사용하는 로직이기 때문에 충돌이 빈번하지 않다고 판단됨
  * 가장 민감한 부분인 돈과 직접 연결되는 부분이기 때문에 데이터의 무결성의 중요도가 높다고 판단
* 장점 
  * 안정성 : 충돌이 빈번한 경우 안정적, 데이터 무결성을 강력하게 보장
  * 데이터 일관성 보장 : 동시성 문제가 발생할 가능성을 차단하여 데이터의 일관성을 보장할 수 있음
* 단점
  * 성능 저하 : 자원을 점유하고 있는 동안 다른 트랜잭션의 진행이 지연되므로, 트래픽이 많거나 자주 충돌이 발생하는 경우 성능 저하가 발생할 수 있음
  * 효율성 : 과도하게 락을 사용하게 되면 시스템 전반적인 효율성이 낮아질 수 있음
## 2.재고 감소 동시성 문제
* 한 제품을 여러 사용자가 동시에 구매하려고 할 때, 재고 수량이 부족하거나 제대로 감소하지 않을 경우.
### Distributed Locking (분산 락)
* 구현 복잡도 ⬆
* 성능 ⬆
* 효율성 ⬆
* 이유
  * 제품은 재고에 관하여 여러 사람이 동시에 접근할 수 있는 부분이라고 판단됨.
  * 제품의 재고가 있고 없음에 따라 주문 여부를 결정할 수 있기 때문에 데이터의 무결성도 중요도가 높다고 판단
* 장점 
  * 확장성 : 여러 서버가 분산 락을 통해 자원을 공유할 수 있어, 트래픽이 높은 분산 환경에서 효율적임
  * 데이터 무결성 보장 : 중앙에서 락을 관리하여 어러 서버에서 데이터 무결성을 보장
* 단점
  * 구현의 복잡도 : 분산 락 관리, 네트워크 연결 등의 추가적인 구현이 필요하며, 이를 관리하는 로직이 복잡
  * 성능 : 네트워크를 통해 락을 관리해야 하므로, 대기 시간이 늘어날 수 있음
